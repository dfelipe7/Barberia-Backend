# REQ-001 — Entorno de desarrollo local multitenant aislado

## 1. Identificador y título

`REQ-001` — Entorno de desarrollo local multitenant aislado (MySQL 8.0 en Docker, sin
tocar `bd_barberia` ni Railway).

## 2. Fecha y solicitante

- Fecha: 2026-10-21 (fecha del commit `8030070`).
- Solicitante: responsable de la ejecución backend del proyecto Barbería.

## 3. Objetivo

Disponer de una base de datos de desarrollo **aislada, reproducible y destruible** que
replique el esquema multitenant del backend (MySQL 8.0) sin enlazar ninguna base de datos
existente (`bd_barberia`) ni ningún servicio remoto (Railway).

## 4. Alcance

Incluye: contenedor MySQL 8.0 con puerto de host propio, fichero de variables de entorno
de desarrollo, scripts de migración/aplicación contra la BD de desarrollo, y
documentación operativa.

Fuera de alcance: cualquier cambio en el esquema de producción, cambios en `bd_barberia`,
despliegues, y la semilla de datos (tratada en `REQ-003`).

## 5. Contexto y estado previo

El repositorio trabajo contra `bd_barberia` (MySQL compartido) y contra Railway. No había
forma de aplicar el historial de migraciones completo de forma reproducible, ni de
ejecutar las pruebas de integración contra un MySQL 8.0 limpio. El `Dockerfile` heredado
no distinguía el entorno de desarrollo del de despliegue.

## 6. Requisitos funcionales

- RF-1. Levantar un MySQL 8.0 aislado con puerto de host propio y credenciales dedicadas.
- RF-2. Separar las variables del entorno de desarrollo del `.env` de producción.
- RF-3. Permitir listar y aplicar migraciones sobre la BD de desarrollo de forma
  idempotente y reproducible.
- RF-4. No requerir credenciales de producción ni de Railway para operar en local.
- RF-5. Documentar el procedimiento en el `README.md`.

## 7. Requisitos no funcionales

- RNF-1. Aislamiento: cero escrituras sobre `bd_barberia` y cero conexiones a Railway.
- RNF-2. Reproducibilidad: la BD se reconstruye desde el historial de migraciones completo.
- RNF-3. Portabilidad: el entorno funciona en Windows, Linux y macOS con Docker.
- RNF-4. Los secretos del entorno de desarrollo **no** se versionan (solo su plantilla).

## 8. Criterios de aceptación

| # | Criterio | Resultado verificado |
|---|----------|----------------------|
| CA-1 | El contenedor `barberia-mysql-multitenant-dev` levanta MySQL 8.0 en el puerto 3308 | Verificado: `docker ps` muestra `mysql:8.0.46`, puerto `3308` |
| CA-2 | `.env.multitenant-dev` no está versionado; `.env.multitenant-dev.example` sí | Verificado: `git check-ignore` sobre `.env.multitenant-dev` |
| CA-3 | `npm run db:migrate:status:dev` lista el historial completo contra la BD de desarrollo | Verificado: salida del script con las migraciones listadas |
| CA-4 | `npm run db:migrate:dev` aplica el historial sin error | Verificado: exit 0 |
| CA-5 | `bd_barberia` no aparece en ninguna ruta de conexión del entorno de desarrollo | Verificado: lectura de `.env.multitenant-dev` y de los scripts de `package.json` |
| CA-6 | El `README.md` documenta el procedimiento | Verificado: sección «Entorno de desarrollo local multitenant» |

## 9. Archivos creados

- `.env.multitenant-dev.example` — plantilla de variables del entorno de desarrollo.
- `docker-compose.multitenant-dev.yml` — definición del MySQL 8.0 aislado.

## 10. Archivos modificados

- `.gitignore` — exclusión de `.env.multitenant-dev` y de los artefactos de desarrollo.
- `.dockerignore` — exclusión de secretos y artefactos locales de la imagen.
- `Dockerfile` — separación de la imagen de desarrollo de la de despliegue.
- `package.json` — scripts `db:migrate:dev` y `db:migrate:status:dev`.
- `README.md` — documentación del entorno de desarrollo.
- `prisma/migrations/20260912145500_agregar_modulo_servicios/migration.sql` — ajuste de
  compatibilidad con MySQL 8.0 estricto.

## 11. Archivos eliminados

Ninguno.

## 12. Dependencias

Ninguna dependencia npm nueva. Se usa Docker + la imagen oficial `mysql:8.0`.

## 13. Pruebas

- Pruebas nuevas: ninguna (este REQ no introduce comportamiento de producto).
- Pruebas ejecutadas: validación manual de CA-1 a CA-6 con `docker ps`,
  `docker compose`, `npm run db:migrate:status:dev`, `npm run db:migrate:dev` y
  `git check-ignore`.
- Resultado: **todas las comprobaciones con salida satisfactoria** (exit 0).
- Suite completa al cierre de la fase: `npm test` → 83 suites / 996 tests;
  `npm run test:multitenant` → 17 suites / 150 tests (ambos en exit 0).

## 14. Riesgos y límites

- Riesgo: el puerto 3308 del host puede estar ocupado en otras máquinas → *Plan B*: cambiar
  el mapeo de puertos en `docker-compose.multitenant-dev.yml`.
- Límite: el entorno reproduce el **esquema**, no el volumen de datos de producción.
- Límite: la semilla de las dos barberías no forma parte de este REQ (ver `REQ-003`).

## 15. Resultado y estado

**COMPLETADA CON LIMITACIONES.** El entorno quedó operativo y aislado, y se verificó
contra MySQL 8.0 real. Las limitaciones son las inherentes al entorno local (volumen de
datos y dependencia de Docker), documentadas en la sección 14.
